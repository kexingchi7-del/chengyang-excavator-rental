# 可选：Gmail 询价入表与每日订单提醒

公开网站通过 FormSubmit 接收询价，本脚本只读取收件 Gmail 并维护私人台账。无需部署 Web App，不需要公开收件邮箱、Sheet ID、脚本属性或访问凭证。代码文件本身不会启动自动化，只有账号所有者完成下列授权与运行后，Google 才会执行定时任务。

## 一次性安装与授权

1. 使用**实际接收 FormSubmit 询价的 Google 账号**登录 https://script.google.com/ ，选择「新建项目」。独立项目即可，不用绑定网站。
2. 把同目录 `Code.gs` 的全部代码粘贴到项目的 `Code.gs`，保存。不要把私人台账共享为「知道链接的任何人」。
3. 打开「项目设置」，将时区设置为 `Asia/Shanghai`（北京时间）。脚本中的日报触发器也明确使用这个时区。
4. 在编辑器函数下拉框选择 `setup`，点击「运行」。首次选择「审核权限」，核对账号，授权 Gmail 读取、电子表格读写、发送邮件及管理触发器。仅在确认是你自己创建的代码时继续 Google 显示的未验证应用提示；组织账号可能需要管理员许可。
5. 运行成功后在「执行日志」读取返回的 `spreadsheetUrl`，打开新表。里面有 `Leads` 和 `Orders`（新文件可能另带一个空白默认工作表，可忽略）。所有者邮箱来自 `Session.getEffectiveUser().getEmail()`，仅保存到私人 ScriptProperties，没有硬编码邮箱。
6. 手动运行 `importFormSubmitLeads`。核对执行日志中的 `imported`，并打开 `Leads` 检查一封真实询价的邮件ID、时间和正文。再次运行应不重复追加同一邮件。
7. 在 `Orders` 按下文填写一条可核对的订单，手动运行 `dailyOwnerDigest`，核对所有者 Gmail 是否收到日报。当天再次运行不会重复发送成功的日报。
8. 左侧「触发器」（时钟图标）确认两个任务：`importFormSubmitLeads` 每小时，`dailyOwnerDigest` 每天北京时间17点所在时段。Google 时间触发器并非精确整点，可能延迟；可把触发器失败通知设为立即通知，并在「执行记录」核对错误。

`setup()` 可重复运行：复用脚本属性中的表格，保留数据，替换**当前账号创建的这两个函数的触发器**。不要让其他账号再安装相同项目触发器；各账号的触发器互不可见。不要删除 `SPREADSHEET_ID` 属性后再运行 setup，否则会创建另一份表。不要改表头或列顺序，脚本会检查并报错保护现有数据。

无需点击「部署」，无需「执行身份/任何人访问」设置，也没有 Web App URL。唯一返回的业务链接是私人表格的 `spreadsheetUrl`；网站的 FormSubmit 地址继续由网站配置负责，本脚本不替换它。

## Leads：导入边界与跟进

搜索条件精确为：

```text
from:submissions@formsubmit.co subject:"新客户询价" newer_than:30d
```

每小时重新搜索近30天，按 Gmail **邮件ID**去重，追加成功后才算已导入。不删除邮件、不改变已读状态，也不会向客户自动发信。主题必须含「新客户询价」，发件人必须匹配；主题含测试/test/激活/activation、激活模板正文、明确测试标记或测试姓名的邮件会跳过。测试主题建议用「新客户询价 测试」；仅在自由备注里写「测试」不会跳过真实客户。导入只依据邮件内容，不把发件人地址匹配视为客户真实性认证。

正文最多保留12000字符，单个解析字段最多1000字符。支持常见中文字段名和英文 name/phone/company/location/project/start/days/hours/machine/count/cooperation/payment/notes；邮件模板变化可能导致拆分字段为空，务必以原始正文和 Gmail 原信核对。输入以 `= + - @` 开头时以文本保存，防止表格公式执行。

`跟进状态`、`负责人`、`跟进备注`供人工维护。保留邮件ID列，不删除已导入行，否则近30天的邮件可能再次导入。询价的天数、机时及报价均为客户意向，**不会自动转为 Orders 的实际工时、实际费用或确认到账**。

每次最多搜索500个会话，达到上限会明确报错，不宣称完整导入；高流量时须调整搜索时间窗口并分段补导。停机超过30天的历史邮件不会自动补齐，须临时调整查询时间范围，同时相应调整 `eligibleMessage_` 中的30天截止限制，然后手动导入。原始邮件仍在 Gmail 中。

## Orders：实际费用、到账和预付款提醒

一行一个订单，按表头填写：

| 列 | 填写口径 |
| --- | --- |
| 订单ID、客户、电话、机型、数量 | 人工识别订单；数量仅作记录，不再次乘入累计机时 |
| 合同小时单价 | 已确认的每台每小时合同价，数字且大于0 |
| 实际累计机时 | 所有机器实际工作小时之和，数字且不小于0；2台各工作8小时填16 |
| 其他实际费用 | 已发生且约定应收的费用合计，数字且不小于0；无则明确填0 |
| 确认累计到账 | 对照银行/微信等凭证确认的累计实收金额，数字且不小于0；确实未收到填0，尚未核实留空 |
| 预计每日总机时 | 所有机器预计每天工作小时之和，数字且大于0；用于两天预付款缓冲 |
| 付款到期日 | 日期单元格或严格 YYYY-MM-DD；未填写则无法判断逾期 |
| 订单状态 | 核对结清后填「已结清」可停止提醒，其他状态继续检查 |
| 备注 | 合同、费用凭证、机时记录和付款约定说明 |

净应收 = 实际累计机时 × 合同小时单价 + 其他实际费用 − 确认累计到账。正数是欠款，负数绝对值是剩余预付款。两天缓冲 = 预计每日总机时 × 合同小时单价 × 2。剩余预付款低于两天缓冲会提醒；到期日早于今天且净应收大于0会标记逾期。当天到期尚不标记逾期。

例如单价750、累计机时16、其他费用0、实际到账15000、每日总机时8：净应收为−3000，剩余预付款3000，两天缓冲12000，提示余额不足。这里的750只是示例，实际填合同价。

单价、累计机时、其他费用、到账、每日总机时任意一项空白/文本/负数会提醒数据无效，不把未知到账默认为0，也不计算误导余额。请在表格中输入数值而非「750元」「待付」等文字。到期日为空且余额充足的订单不会单独触发提醒；要完整检查逾期必须补齐到期日。台账需你或负责人持续录入实际数据，脚本不读取银行流水、不自动确认付款。

## 日报、额度与恢复

日报按Leads追加行数统计上次成功日报后导入的线索（首次为所有已导入），不会因为邮件收到时间较早而漏掉延迟导入的询价。请勿删除、排序或重排Leads原始记录；需要排序时使用筛选视图。日报还包含最近成功导入时间、数据缺失/预付款不足/逾期订单和私人台账链接。超过3小时未成功导入会提示检查执行记录。最多列出100条订单提醒，其余请打开表格检查。

同一天成功发送后使用 ScriptProperties 去重；发送失败不写成功标记，额度恢复后可手动运行或等待下次每日触发器重试。Gmail 读取或脚本运行额度耗尽时，本次导入失败，已入表的邮件保留，下次小时触发器按ID补导。Google 邮件发送与属性写入不是一个事务：极少数情况下邮件成功但标记失败，重试可能重复；不承诺严格一次送达。

授权持续有效时不需要每次保持浏览器登录；账号撤销授权、组织策略变化、删除项目/触发器会停止执行。修改权限后可能需要重新在编辑器授权。检查 Google 当前的 [Apps Script 额度](https://developers.google.com/apps-script/guides/services/quotas)，个人 Gmail 和 Workspace 额度不同且可能调整；发送额度按收件人数计，另有 Gmail 读写、触发器总运行时间等限制。成功运行并核对实际表格和收件箱后，才能确认你账号中的自动化已启用；本仓库文件交付不代表已完成账号授权或启动。
